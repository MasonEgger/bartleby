# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Bartleby is an agents-first, batteries-included Python static site generator. The full specification is in `spec.md`.

**Positioning (confirmed 2026-08-08):** Bartleby leads as an *agents-first* SSG. Its differentiator is treating AI crawlers and coding agents as a first-class audience alongside humans: per-page Markdown variants, `llms.txt`/`llms-full.txt`, `schema.json`, `content-index.json`, JSON-LD, and deterministic skill generation. This is a deliberate choice not to compete with Zensical (the Material for MkDocs team's Rust-core, docs-focused rewrite) on build performance or docs-team ergonomics. Solid docs/blog output is table stakes; the agent surface is where the work goes. Bartleby stays MIT and free (see the strategic-direction note in memory).

## Architecture

Bartleby is 39 single-responsibility modules under `src/bartleby/`, grouped by build-pipeline phase (see spec.md "Component boundaries"). The key architectural decisions:

- **Frontend stack**: Tailwind CSS + Alpine.js + HTMX + lunr.js (reimplemented, NOT ported from mkdocs-material)
- **Synchronous build**: `build()` in `build.py` runs the whole pipeline in-process. `async_build()` is only an `asyncio.to_thread` wrapper used by the CLI `build` command. Parallel and incremental builds are explicit non-goals (spec.md).
- **Co-located assets**: Non-markdown files in `content/` follow the page's output URL, not the source path (Hugo-style page bundles)
- **Theme system**: resolution goes through `theme_loader.py` plus bundled themes under `themes/` (`base`, `material`, `scrivener`). The default theme (`DEFAULT_THEME_NAME`) is `scrivener` (system sans, neutral palette, one accent; its design note is in `tailwind.config.js`). Tests that need material must name it through `tests/theme_helpers.py::material_theme()`. `base` owns the shared theme-neutral helpers: `partials/nav_macros.html` (`holds`, `first_url`) and `partials/toc_macros.html` (`entries`, `tracker`), imported by both material and scrivener. `base` also owns the search engine: `themes/base/static/js/search.js` exposes the Alpine component `bartlebySearch` (refs `trigger` and `input`; the highlight flag arrives as `data-highlight` with `tojson` on the script tag), loaded from `base.html` when `search` is on. The search modal is placed by `base.html`, which includes `partials/search.html` on every page when search is on, so a theme cannot drop it by overriding its header. A theme's trigger opens the modal by dispatching a `bartleby:search-open` window event; `search.js` `init()` handles that event and also binds the `/` and Ctrl/Cmd+K shortcuts (both preventDefault), and `close()` refocuses the `trigger` ref or the previously active element. Theme search partials are markup only. A theme is a directory with a `theme.yml` manifest, selected by `theme.name`, `theme.path`, or `theme.package`, composable with `extends`, and exposed whole by `bartleby theme eject` and `theme inspect`. The theme vocabulary is Bartleby-native; do not add mkdocs-material alias keys. Each theme's `tailwind.config.js` owns its safelist (it reads the sibling `safelist.txt`), because the compile passes `--content`, which overrides config content; a component class in `tailwind.css` that no template references must be listed there or Tailwind purges it. Under `nav.tabs` the sidebar title is the section itself, and with `nav.section-index` it links to the index page and carries that page's folded TOC (`nav.toc-fold`), because `tree()` skips the index child there. Nav directory targets (`dir/`) and auto-nav sections expand into sections in `navigation.py` (pages as children sorted by title, subdirectories nested, `index.md` supplies `url`/`index_url` and stays the first child), except directories that are or contain a content-type path, which stay plain listing links. `build.py` sets `page.toc` from the renderer's `toc_tokens` for every theme. Material's palette is forest green (primary `#1f801f`, light links `--bm-primary-dark`, accent `#2e7d32`, dark-mode link `#6fbf6f` and accent `#8fd48f`); `tests/test_theme_contrast.py` reads those hexes out of `tailwind.css` and pins each text-on-color pair at its WCAG ratio, so a palette edit must update the pins. Neither bundled theme draws a colored left rule on admonitions, `details`, or fence environment blocks; the only `border-left` rules are navigation.
- **Color mode**: `themes/base/templates/base.html` owns the inline pre-paint script that sets `data-theme` (stored choice in localStorage `bartleby-color-mode`, then `theme.color_mode.default`, then `prefers-color-scheme`). Both bundled themes include the shared switch `partials/color_mode_toggle.html` from `base`, which writes that same key; do not duplicate the script or the toggle per theme.
- **Dev server**: `server.py` serves the built site and the live-reload WebSocket from one Starlette app (`build_app`, which takes the static app) run in-process by uvicorn, on one port. `_ReloadInjectingFiles` is a `StaticFiles` subclass (directory `index.html`, the theme's `404.html`, content types) that injects `reload_snippet()` into `.html` responses as bytes (any encoding serves; a page that vanishes mid-swap is a 404), and `serve_from` repoints it when `output_dir` changes between rebuilds. `_bind` picks the socket family from `getaddrinfo` (IPv4 preferred when a host has both; `::1` binds IPv6 and `url_host` prints it in brackets); a busy port raises `ServeBindError`, port 0 resolves before the URL prints, and `stop()` ends `run` from another thread. Uvicorn's own logging is off. The watchdog handler only forwards paths (file create, modify, move, delete; directory delete and move) and `_on_watched_change` enqueues the watched ones; one worker thread (`_drain_changes`) waits for the queue to stay quiet for `quiet_window` (100 ms) and runs one synchronous `rebuild()` per burst through `_rebuild_for`, then hands the reload broadcast to the server's event loop. `rebuild()` turns every exception into a `PageError` (labeled errors through `_labeled_page_error`, anything else as `Type: message`), so the worker never dies; a failed rebuild keeps serving the last good output, sends no reload, and prints `error: <path>: <message>` to stderr in text mode or an `error` event under `--events`. `is_watched` and `classify_change` stay the event filter; both take the resolved theme's directory prefixes, which `watch_theme` records (in-project roots through the project observer, outside roots through an extra scheduled watch; bundled themes are not watched). Each failure has a test in `tests/test_server.py`.
- **Scaffold**: `bartleby new site` copies `src/bartleby/scaffold/` (package data) with `string.Template` (`${name}`, `${title}` for the name as a JSON-quoted YAML scalar, `${today}`); edit the starter files there, not in `cli.py`. Any failure after the target `mkdir` removes the directory before re-raising.
  `--blog` also copies `src/bartleby/scaffold_blog/` and merges the blog block into `bartleby.yml`, and directories in `_VERBATIM_STARTER_DIRS` (`content/tour/`, which shows `$` math) are copied byte for byte rather than through `string.Template`.
  `--full-config` renders `config_edit.render_full_config(CONFIG_SCHEMA, base=<starter text>)` over the starter, keeping its values and emitting the `<name>` examples as commented-out YAML.
  `_merge_content_shape` in `cli.py` is the one path `enable` and `--blog` share: it adds the type block, missing taxonomies, and a `nav` entry when `nav` is explicit and lacks one.
- **Config file I/O**: `config.read_config_text` is the only read of `bartleby.yml` and `config_edit.write_config_text` the only write (temp file beside the target, then `os.replace`); both turn `OSError` into `ConfigError`. PyYAML loads go through `config._StrictLoader`, which rejects a repeated key, and every ruamel load goes through `config_edit._load_document`, so `validate` and `config set` agree. `config set` and `--set` type a value with `config_schema.override_value`: a string key keeps the text verbatim (empty text unsets it), every other key parses YAML and must match the schema type, and a path the schema lacks is refused with a difflib hint unless it sits under an open `mapping` field (`markwright`, `theme.tokens`, `theme.icon_packs`, `ai.robots`). `config.DOTTED_KEY_SECTIONS` makes `split_path` keep everything after `theme.tokens` as one key. `apply_overrides` imports `override_value` inside the function because `config_schema` reads `config` at import. The `markwright` section is validated at load time by `config.markwright_config`, which the renderer also calls. Tests that edit a config fixture use `tests/config_helpers.py::replace_top_level_keys`, since appending a second `theme:` block is now a duplicate-key error.
- **Error messages**: `errors.format_error(message, *, source=None, key_path=None, hint=None)` is the only place an error string is assembled. It returns `<source>: <key path>: <message> (fix: <hint>)` and drops absent parts. `ConfigError`, `AuthorError`, `ThemeError`, `ShortcodeError`, and `AgentSurfaceError` carry `hint` and `source` and build `__str__` through it; new error types must do the same. Every user-facing error needs a concrete fix hint, and the CLI maps each type to a code in `_ERROR_CODES` (no tracebacks).
- **Output swap**: `build._swap_output_into_place` moves the old output into a sibling `.bartleby-old-*` holding directory, moves the new tree in, then deletes the old one; a failed move puts the old output back. It follows a symlinked output directory (the link stays), refuses a target that holds `bartleby.yml` or `content/`, and the staging directory from `mkdtemp` is chmod'ed to the umask's mode. `config._validate_output_dir` rejects an `output_dir` that is the project, an ancestor, or overlaps `BUILD_INPUT_DIRS` or a `theme.path` directory. `BuildResult.output_dir` comes from `display_output_dir`: project-relative under the project, absolute otherwise.
- **Extension ordering**: markwright.fence preprocessor (priority 40) runs BEFORE pymdownx.superfences (priority 25). The fence postprocessor then injects results AFTER superfences generates HTML.
- **Accessibility pass**: `accessibility.py` is the last extension `create_markdown_renderer` registers, so every theme gets the same cues. A treeprocessor (priority 3) prepends an inline Octicon (`class="admonition-icon"`, `aria-hidden`) and, for a custom title, a `<span class="visually-hidden">Type: </span>` to each admonition title and `details` summary; the map is `ADMONITION_ICONS` (unknown types get `info`), and icons resolve through `icons.get_icon_path` with the chain's `icons_dirs()` (build.py passes `state.theme.icons_dirs()`), so a theme overrides a glyph by shipping `icons/octicons/<name>-16.svg`. Fenced blocks and task-list checkboxes are stashed strings, not tree elements: the "Environment NAME." span and the markwright embed repairs (YouTube title, image-compare label, slideshow focus) are postprocessors at priority 15 (after markwright's `mw-fence-post` at 25), and the checkbox `aria-label` is written into `md.htmlStash.rawHtmlBlocks` by index from the item's placeholder. Tables get `tabindex="0"`. `base.html` owns the inline `.visually-hidden` and `.skip-link` rules, the "Skip to content" link (first in the body, to `main#main-content`), and `lang` from `site.language` (default `en`); `search.js` traps Tab inside the open dialog via `this.$root`. Both themes style `.admonition-icon`, print the environment name as a `pre.environment-*::before` tag (left of the Copy button through `:has`), and must keep the global `prefers-reduced-motion` rule. `tests/test_accessibility.py` builds the scaffold with both themes and pins all of this; `tests/test_theme_contrast.py` pins muted and faint text on every surface and environment tint (material muted is a 68% mix, faint 50%; scrivener muted 72% light, 68% dark) and the focus rings at 3:1. Material prose links are always underlined (the link green is 2.27:1 against the text). Audit with axe-core through Playwright, not by eye; the remaining findings are third-party iframes.
- **Bundled extension options**: `markdown_pipeline._BUNDLED_EXTENSION_CONFIGS` sets `pymdownx.tabbed` (`alternate_style`), `pymdownx.arithmatex` (`generic`, so math is `\(...\)` and `\[...\]` in `.arithmatex`), and `pymdownx.emoji` (twemoji with `to_alt`, so emoji are characters and no CDN image loads). A `markdown_extensions` override merges over the bundled entry (override keys win). `emoji_index` and `emoji_generator` are dotted-path strings (`pymdownx.emoji.to_svg`) resolved by `_resolve_emoji_callables`, for the defaults and user overrides alike; do not import `pymdownx` (no stubs).
- **Fence environment warning**: markwright's `warn` is read only by its CLI, so Bartleby defaults it on in `config.markwright_config` and does the check itself: `fence_environment_limits` reads `allowed_environments` when the report applies, `disallowed_environments` walks fenced blocks with `markwright._fences.find_fenced_blocks` and the leading-directive rule, and `build._render_page_bodies` logs one `format_error` line per name per page. `warn: false` in the section silences it.

## Tech Stack

- Python 3.14+, uv for package management
- Python-Markdown + pymdownx + markwright for rendering
- Jinja2 for templates, argparse for CLI
- pytest for testing, ruff for linting, mypy (strict) for type checking
- Tailwind CSS standalone CLI for theme compilation (no Node dependency for users)

## Build & Development Commands

```bash
uv sync                    # Install dependencies
just check                 # The gate: ruff lint + format check, mypy strict, pytest, e2e smoke
just lint | typecheck | test | smoke | format   # Individual targets
just theme-css             # Recompile the shipped theme CSS via `python -m bartleby.theme_compile` (needs tailwindcss on PATH or --binary; shares the content globs with user sites; package-build only)
uv run pytest tests/test_config.py  # Run single test file
uv run pytest -k "test_name"        # Run single test by name
(cd docs && uv run bartleby build)  # Build the docs site (itself a Bartleby site; output in docs/site/, gitignored)
```

Hold every diff to `just check`; `uv run pytest` alone skips ruff, mypy, and the smoke test.

## Code Style

- All files start with a 2-line comment: first line prefixed with `ABOUTME: ` (grep-friendly)
- Strict type hints everywhere: mypy strict mode, no `Any` escape hatches
- Test-driven development: write tests first, then minimal code to pass
- Single responsibility per function/module
- Validate at system boundaries only (trust internal code)
- Never name things "improved", "new", or "enhanced": names must be evergreen
- Preserve existing code comments unless actively false
- No em or en dash anywhere in the tree (templates, ABOUTME lines, docstrings, tests): the page title and 404 heading use ` - `, and comments use a colon, comma, or semicolon
- Do not add error handling for impossible scenarios

## Module style (YAML-backed modules)

Bartleby has several modules that parse YAML config or content into typed dataclasses. They all share the same skeleton; reuse it when adding new ones:

- `from __future__ import annotations` at the top so type hints are strings
- `if TYPE_CHECKING:` block for runtime-unused imports (`Path`, sibling-module types) to keep them out of the runtime import graph and silence ruff `TC003`
- Type the YAML boundary as `Any` (because `yaml.safe_load` returns `Any`), then narrow with `isinstance` checks inside per-section parse helpers; keeps mypy strict happy without casting churn
- Use `@dataclass(slots=True)` for the typed result objects; `field(default_factory=...)` for mutable defaults
- Custom exception type per module (`ConfigError`, `AuthorError`, `ShortcodeError`, …) with a structured field where helpful (e.g. `ConfigError(message, key_path)`)

Look at `src/bartleby/config.py` and `src/bartleby/authors.py` for the canonical patterns.

## Where Things Are Defined

- `spec.md` is the living product spec (canonical). Its sections: Starting context, Project overview, Available tooling, External tool candidates, Goals, Non-goals, Roadmap / phase log (with the Deferred list), Component boundaries, Success criteria. Nothing may implement a Non-goal or a Deferred item without a spec change first.
- `plan.md` and `todo.md` are the current BPE plan (Goal 8: 19 steps, 8 sections) and its checkbox mirror. `.ai-sessions/` is tracked: session summaries and `lessons.md` are committed; only `implementation-notes.md` and `handoffs/` stay local. The BPE goal loop requires a new session summary in every commit.
- Plugin hooks: the 16 `on_*` methods on the base class in `plugins.py` are the public hook API.
- Template lookup: `template_search_bases()` in `templates.py` is the single source of truth for the cascade (project `overrides/`, `templates/`, project root, then the theme); `resolve_template_name()` picks the per-page candidate.
- Section layout: `doc_layout.html` (in `scrivener` and `material`) is the shared page/post/listing layout; it includes `partials/section_nav.html` from `base` for the section sidebar and TOC. `navigation.py` still maps a content-type directory to one nav link; authors list pages under it in `nav` to get a sidebar.
- Taxonomy URLs: `taxonomies.term_url` is the single builder, used by page generation and by `Page.taxonomy_links` (`TermLink`, `url=None` when the term has no page). Posts in a content type link to its scoped term page.
- Excerpts: `Page.excerpt` is plain text (feeds, llms.txt); `Page.excerpt_html` is rendered and crossref-rewritten (list and taxonomy templates). The agent surface uses `description`.
- Agent surface: `llm.py` (Markdown variants, `llms.txt`, JSON-LD), `agent_surface.py` (`schema.json`, `content-index.json`), `schema_introspection.py`, `skills.py` (deterministic skill generation). This is the differentiator; keep it the most consistent part of the tool.
- Absolute URLs: `urls.absolute_url` is the single builder for site-absolute URLs (seo, sitemap, feeds, llm, agent_surface all use it). Do not add per-module copies.
- `schema.json` carries a `theme` block `{name, chain, features: {enabled, implemented, active}}`; `active` is the intersection and the value agents should rely on. The four agent files (`llms.txt`, `llms-full.txt`, `schema.json`, `content-index.json`) are byte-identical across builds and a test pins it.
- `export --include-html` renders through `build.render_content`, which shares `_render_page_bodies` with the build.
- Global CLI flags: `cli._global_flags()` holds the real defaults on the top-level parser; each subparser attaches `_global_flags(on_subcommand=True)`, whose defaults are `argparse.SUPPRESS`, so `bartleby --output json validate` keeps the value and a flag after the subcommand name still wins. Do not put defaults back on the subparser copies.
- Prose that quotes a number: `tests/test_docs_reference.py` pins the module count in README.md, CLAUDE.md, and spec.md to the files under `src/bartleby/`, the README Architecture list to those files, and the `Ejected theme ... (N files)` line in the docs to a real eject. `tests/test_acknowledgments.py` scans every theme template for an inline `<svg>` with a `<path d=` and requires ACKNOWLEDGMENTS.md to name the file (or an in-test allowlist of Bartleby-original drawings).
